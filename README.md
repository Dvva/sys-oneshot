# sys_oneshot

Windows 上那些「跑一次就完事」的补丁：改完某个软件或系统的一处行为，之后长期生效，随时能撤销。

不是每天要跑的脚本，也不是常驻服务。每个补丁管一件事，带检测、带卸载、卸载前自动备份。

## 收录了什么

| 补丁 | 类型 | 干什么 |
|---|---|---|
| `BandiView-按反引号删除当前文件夹` | 软件 | 在 BandiView 看图时按 `` ` `` 一键把当前图片所在文件夹丢进回收站，并自动切到下一个文件夹 |
| `关闭Edge下载安全警告` | 系统策略 | 让 Edge 对 exe / reg / bat / msi 等 18 种文件不再弹「不常下载，可能有危险」 |
| `迅雷-屏蔽推广弹窗` | 软件 | 拦掉迅雷的会员付费弹窗和活动推广页（hosts + 禁用插件 + 改本地配置） |

## 怎么用

```powershell
cd D:\__Codes\sys_oneshot

.\运行全部.ps1                    # 只看状态，什么都不改
.\运行全部.ps1 -Apply             # 应用所有「未生效」的（已生效的自动跳过）
.\运行全部.ps1 -Apply -Name 迅雷   # 只跑匹配的
.\运行全部.ps1 -Restore -Name 迅雷 # 卸载匹配的
```

`-Name` 是模糊匹配；匹配到多个会停下来让你写得更具体，不会替你猜。
`-Restore` 必须带 `-Name`——批量应用最多是白跑一遍，批量卸载是几十处系统改动一起撤，不给你一键全撤的机会。

也可以进补丁目录双击 `应用.cmd` / `卸载.cmd`，需要管理员的会自动请求提权。

## 为什么「跑过就跳过」不是靠台账

`已应用清单.md` 只记历史，不参与判断。判断靠每个补丁自己的 `-Detect`：真的去查注册表键在不在、hosts 里有不有屏蔽块、文件装没装。

因为台账会骗人——你可能手动改回去了，系统更新把注册表重置了，别的软件覆盖了 hosts。实测不会。要强行重跑加 `-Force`。

## 每个补丁长什么样

```
补丁名（中文，说清给哪个软件解决什么问题）/
├─ 应用.ps1      全部逻辑，必须支持 -Detect / -Restore / -Force
├─ 卸载.ps1      等价于 应用.ps1 -Restore
├─ 应用.cmd      双击入口
├─ 卸载.cmd      双击入口
├─ 说明.txt      给用户看的：功能、影响、怎么还原
└─ _备份\        每次卸载前自动生成的注册表 / 配置备份（不进 git）
```

`应用.ps1 -Detect` 的退出码约定：`0` 已生效、`1` 未生效、`2` 不适用（比如软件没装）。

新增补丁照这个结构放一个目录就能被 `运行全部.ps1` 认出来，不用改入口。

## 每个补丁文件干什么

| 文件 | 作用 |
|---|---|
| `应用.ps1` | 全部逻辑。不带参数=应用，`-Detect` 只检测，`-Restore` 卸载，`-Force` 已生效也重跑 |
| `卸载.ps1` | 只做一件事：转发 `应用.ps1 -Restore` |
| `应用.cmd` / `卸载.cmd` | 双击入口；需要 HKLM 或 hosts 的会在里面自动请求管理员权限 |
| `说明.txt` | **只写这个补丁独有的东西**：功能、改了哪里、副作用、怎么还原。通用用法看本文档 |
| `_备份\<时间戳>\` | 卸载前自动生成，不进 git |

## 还原与备份

所有卸载入口都是**先备份、再动手**：

- 备份落在该补丁目录的 `_备份\<时间戳>\` 下，内容是注册表导出（`.reg`）或配置文件副本
- 备份失败会**中止卸载**，不会出现「删了但没备份」
- 想手工退回：双击备份目录里的 `.reg` 即可，不必跑卸载脚本
- `_备份\` 是本机状态，已 gitignore

## 警告

这些补丁会改注册表（含 `HKLM` 策略）、hosts、第三方软件的安装目录。**跑之前看清楚 `说明.txt`**，尤其是「副作用」那节。

每个卸载入口都会先备份再动手，备份落在对应补丁目录的 `_备份\<时间戳>\` 下；备份里的 `.reg` 双击也能单独还原。

本仓库按「我自己的机器能用」的标准维护，不保证适配你的系统。看完代码再用。
